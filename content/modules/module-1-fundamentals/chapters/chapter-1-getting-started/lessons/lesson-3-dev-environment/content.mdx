# Setting Up Your Development Environment

> **💡** *Setting up a dev environment for AI engineering is like packing for a camping trip—you'll survive with just a tent, but a good sleeping bag, headlamp, and bug spray make all the difference. Same here: Python works alone, but virtual environments, API key management, and the right tools turn survival into comfort.*

## Overview

A proper development environment is crucial for AI engineering. This lesson covers setting up Python, virtual environments, API keys, and essential tools. Getting this right from the start saves hours of debugging later—dependency conflicts, API key leaks, and version mismatches are the most common beginner mistakes.

In 2024-2025, the Python AI ecosystem has matured significantly. Python 3.10+ is the standard, and modern tools like `ruff` (replacing `flake8` + `black` + `isort`) and `uv` (fast package manager) have emerged. We'll cover both the tried-and-true approaches and the latest tools.

## Main Content

### Python Setup

#### Recommended Python Version

Use **Python 3.10 or higher** (3.11+ recommended) for best compatibility with modern AI libraries. Python 3.9 is end-of-life, and 3.12+ offers better performance and features.

```bash
# Check Python version
python --version
# Should show Python 3.10.x, 3.11.x, or 3.12.x

# If you need to install/upgrade Python:
# macOS: brew install python@3.11
# Linux: Use your distribution's package manager
# Windows: Download from python.org
```

#### Virtual Environments

**Why Virtual Environments?**
- Isolate dependencies per project
- Avoid version conflicts between projects
- Reproduce environments easily (via `requirements.txt`)
- Keep your system Python clean

**Using `venv` (Built-in, Recommended for Most Cases)**

```bash
# Create virtual environment
python -m venv venv

# Activate (macOS/Linux)
source venv/bin/activate

# Activate (Windows PowerShell)
venv\Scripts\Activate.ps1

# Activate (Windows Command Prompt)
venv\Scripts\activate.bat

# You should see (venv) in your terminal prompt
# Deactivate when done
deactivate
```

**Using `uv` (Fast, Modern Alternative)**

`uv` is a new, extremely fast Python package manager written in Rust. It's great for creating environments and managing dependencies:

```bash
# Install uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# Create virtual environment (much faster than venv)
uv venv

# Activate
source .venv/bin/activate  # macOS/Linux
.venv\Scripts\activate     # Windows

# Install packages (faster than pip)
uv pip install openai langchain
```

**Using `poetry` (For Larger Projects)**

Poetry manages both dependencies and project metadata:

```bash
# Install poetry
curl -sSL https://install.python-poetry.org | python3 -

# Create new project
poetry new my-ai-project
cd my-ai-project

# Add dependencies
poetry add openai langchain

# Activate environment
poetry shell
```

Always create a `requirements.txt` file for reproducibility:


### API Key Management

**Critical Security Rule: Never commit API keys to git!**

API keys are like passwords—if exposed, attackers can use them to make requests on your behalf, racking up charges or accessing your data. Treat them as secrets.

#### Step 1: Create a `.env` File

Create a `.env` file in your project root (same directory as your code):

```bash
# .env
OPENAI_API_KEY=sk-proj-...
ANTHROPIC_API_KEY=sk-ant-...
PINECONE_API_KEY=...
# Add other API keys as needed
```

**Important Notes:**
- Never add quotes around values in `.env` files
- Don't include spaces around the `=` sign
- One key per line
- You can add comments with `#`

#### Step 2: Use `python-dotenv` to Load Environment Variables

```python
from dotenv import load_dotenv
import os

# Load variables from .env file
load_dotenv()

# Access environment variables
openai_api_key = os.getenv("OPENAI_API_KEY")
anthropic_api_key = os.getenv("ANTHROPIC_API_KEY")

# Verify keys are loaded (optional, for debugging)
if not openai_api_key:
    raise ValueError("OPENAI_API_KEY not found in environment variables")
```

**Alternative: Using Environment Variables Directly**

On macOS/Linux:
```bash
export OPENAI_API_KEY="sk-proj-..."
python my_script.py
```

On Windows:
```powershell
$env:OPENAI_API_KEY="sk-proj-..."
python my_script.py
```

**Note**: Environment variables set this way only last for the current terminal session. Use `.env` files for persistence.

#### Step 3: Add `.env` to `.gitignore`

Create or update your `.gitignore` file:

```gitignore
# Environment variables
.env
.env.local
.env.*.local
*.env

# Python
__pycache__/
*.py[cod]
*$py.class
*.so
.Python
venv/
env/
ENV/
.venv/

# IDE
.vscode/
.idea/
*.swp
*.swo

# OS
.DS_Store
Thumbs.db
```

**Verify `.env` is ignored:**
```bash
git status
# .env should NOT appear in the list
```

#### Step 4: Create a `.env.example` File

Create a template file that others can copy:

```bash
# .env.example
OPENAI_API_KEY=your-openai-api-key-here
ANTHROPIC_API_KEY=your-anthropic-api-key-here
PINECONE_API_KEY=your-pinecone-api-key-here
```

Commit `.env.example` to git so team members know what environment variables are needed. They can copy it:
```bash
cp .env.example .env
# Then edit .env with their actual keys
```

#### Version Control

**Git** (Essential)
- Track code changes
- Collaborate with teams
- Never commit:
  - `.env` files
  - `__pycache__/` directories
  - API keys
  - Large model files (use Git LFS if needed)

#### Code Quality Tools

**Ruff** (Modern, Fast, Recommended)
- Replaces: `flake8`, `isort`, `black` (formatter mode), `pydocstyle`
- Extremely fast (written in Rust)
- Zero-configuration works well
- Install: `pip install ruff`
- Run: `ruff check .` and `ruff format .`

**Black** (Traditional Formatter)
- Opinionated code formatter
- Install: `pip install black`
- Run: `black .`
- Can be used alongside Ruff (Ruff for linting, Black for formatting)

**mypy** (Type Checking)
- Optional but recommended for larger projects
- Catches type-related bugs
- Install: `pip install mypy`
- Run: `mypy .`

#### Testing

**pytest** (Standard)
- Most popular Python testing framework
- Great for testing AI systems
- Install: `pip install pytest pytest-asyncio`
- Run: `pytest`

#### Package Management

- **pip**: Standard, works everywhere
- **poetry**: Better dependency management for larger projects
- **uv**: Fastest option (new, written in Rust)
- **conda**: If you need specific Python versions or system dependencies

## Code Examples

### Complete Setup Example

Here's a complete, production-ready example showing the proper setup:

**Step 1: Create `requirements.txt`**

```txt
# requirements.txt
openai>=1.0.0
python-dotenv>=1.0.0
tiktoken>=0.5.0
```

**Step 2: Create `.env` file**

```bash
# .env (DO NOT COMMIT THIS FILE!)
OPENAI_API_KEY=sk-proj-your-actual-key-here
```

**Step 3: Create `.env.example` (commit this to git)**

```bash
# .env.example
OPENAI_API_KEY=your-openai-api-key-here
```

**Step 4: Create `main.py` with proper error handling**

```python
# main.py
import os
from dotenv import load_dotenv
from openai import OpenAI

# Load environment variables from .env file
load_dotenv()

# Initialize OpenAI client (v1.0+ API)
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# Verify API key is set
if not os.getenv("OPENAI_API_KEY"):
    raise ValueError(
        "OPENAI_API_KEY not found. "
        "Please set it in your .env file or environment variables."
    )

def test_openai_connection():
    """Test OpenAI API connection with a simple request."""
    try:
        response = client.chat.completions.create(
            model="gpt-4o-mini",  # Cost-effective model for testing
            messages=[
                {"role": "user", "content": "Say 'Hello, world!' if you can read this."}
            ],
            max_tokens=50,
        )
        
        message = response.choices[0].message.content
        print(f"✅ Connection successful! Response: {message}")
        return True
        
    except Exception as e:
        print(f"❌ Connection failed: {e}")
        return False

if __name__ == "__main__":
    print("Testing OpenAI API connection...")
    test_openai_connection()
```

**Step 5: Create `.gitignore`**

```gitignore
# Environment variables
.env
.env.local
*.env

# Python
__pycache__/
*.py[cod]
venv/
env/
.venv/
```

**Key Changes from Old Code:**
- Uses `OpenAI()` client (v1.0+ syntax) instead of `openai.api_key`
- Uses `client.chat.completions.create()` instead of `openai.ChatCompletion.create()`
- Uses `gpt-4o-mini` (latest cost-effective model) instead of `gpt-3.5-turbo`
- Includes proper error handling
- Follows current best practices

## Common Mistakes

#### 1. Committing API keys to git
This is the #1 mistake beginners make. Once committed, the key is in git history forever (even if you delete it later). Use `.env` files, add them to `.gitignore`, and always verify with `git status` before committing. If you've already committed a key, rotate it immediately—don't try to remove it from history.

#### 2. Not using virtual environments
Installing packages globally leads to version conflicts between projects. Your system Python becomes a mess of incompatible packages. Always create a virtual environment per project, even for small scripts.

#### 3. Using outdated package versions
AI libraries change rapidly. Using old versions (like `openai==0.27.0`) means missing bug fixes, security updates, and new features. However, don't update blindly—test updates in a separate environment first. Use `pip list --outdated` to check for updates.

#### 4. Hardcoding secrets in code
Never write `api_key = "sk-..."` directly in your code. Use environment variables or secrets management. Hardcoded keys get committed, exposed in screenshots, logged, and shared in code reviews.

#### 5. Not pinning dependency versions in production
Using `openai>=1.0.0` is fine for development, but production should use exact versions (`openai==1.12.0`) to ensure reproducible deployments. Consider using `pip freeze > requirements.txt` to generate exact versions, or use `poetry` which manages this better.

#### 6. Ignoring Python version compatibility
Some AI libraries require specific Python versions. Always check the library's documentation for Python version requirements. Python 3.9 is end-of-life, use 3.10+.

#### 7. Not having a `.env.example` file
Without a `.env.example`, team members don't know what environment variables are needed. Always create a template file showing required variables (without actual values).
