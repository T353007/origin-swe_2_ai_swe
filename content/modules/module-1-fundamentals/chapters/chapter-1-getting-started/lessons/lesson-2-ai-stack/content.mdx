# The Modern AI Stack

## Overview

The AI engineering stack consists of LLM providers, vector databases, frameworks, evaluation tools, and observability platforms. Understanding this stack helps you choose the right tools for your projects.

## Main Content

### Core Components

#### 1. LLM Providers
- **OpenAI**: GPT-4, GPT-3.5, embeddings
- **Anthropic**: Claude models with longer context windows
- **Google**: Gemini, PaLM
- **Open Source**: Llama, Mistral, etc.

#### 2. Vector Databases
Store and search embeddings efficiently:
- Pinecone (managed)
- Weaviate (self-hosted or managed)
- Qdrant (self-hosted)
- Chroma (lightweight, Python-first)

#### 3. Frameworks & Orchestration
- **LangChain**: Popular framework for building LLM applications
- **LlamaIndex**: Focus on data ingestion and retrieval
- **Haystack**: Open-source NLP framework
- **Semantic Kernel**: Microsoft's framework

#### 4. Evaluation & Testing
- LangSmith: Evaluation and debugging
- Phoenix: Open-source observability
- Custom eval frameworks

#### 5. Observability & Monitoring
- Tracing: LangSmith, OpenTelemetry
- Logging: Structured logging for prompts/responses
- Metrics: Latency, cost, quality scores

## Code Examples

Basic stack integration example:

```python
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_pinecone import PineconeVectorStore

# Initialize components
llm = ChatOpenAI(model="gpt-4", temperature=0)
embeddings = OpenAIEmbeddings()

# Initialize Pinecone vector store (assuming index already exists)
vectorstore = PineconeVectorStore(index_name="my-index", embedding=embeddings)

# Simple RAG chain
def answer_question(question: str) -> str:
    # Step 1: Retrieve relevant documents
    docs = vectorstore.similarity_search(question, k=3)
    
    # Step 2: Build context from retrieved documents
    context = "\n".join([doc.page_content for doc in docs])
    
    # Step 3: Construct prompt with context
    prompt = f"Context: {context}\n\nQuestion: {question}\n\nAnswer:"
    
    # Step 4: Generate answer using LLM
    response = llm.invoke(prompt)
    return response.content
```

## Common Mistakes

1. **Tool overload**: Don't use every framework; choose based on needs
2. **Vendor lock-in**: Consider abstraction layers for LLM providers
3. **Ignoring costs**: Vector DBs and LLM APIs can get expensive
4. **No observability**: Deploying without tracing makes debugging impossible
