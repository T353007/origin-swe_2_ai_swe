# Model Parameters and Temperature

> **💡** *Model parameters are like the dials on a mixing board - turn temperature too high and your code explanations become poetry, turn it too low and creative writing becomes technical documentation. The trick is finding the right settings for each task, which is easier said than done when "creativity" is measured on a scale of 0 to 2.*

## Overview

Model parameters control how LLMs generate text. Understanding temperature, top_p, max_tokens, and other parameters is crucial for getting consistent, high-quality outputs that match your use case. The same prompt with different parameters can produce dramatically different results - a fact that surprises many developers who expect deterministic behavior.

In 2024-2025, understanding these parameters has become even more important as models like GPT-4o have become more sensitive to parameter tuning. Getting parameters right can be the difference between a production-ready system and one that produces inconsistent, unusable outputs.

## Main Content

### Key Parameters

Understanding these parameters is essential for controlling model behavior. Each parameter affects different aspects of text generation.

#### Temperature (0.0 to 2.0)

Temperature controls the randomness/creativity of the model's outputs. Think of it as how "confident" the model needs to be before choosing a word.

**How it works:**
- Lower temperature (0.0-0.3): Model chooses the most likely tokens. More deterministic, focused, and consistent.
- Medium temperature (0.5-0.7): Balanced between determinism and creativity.
- Higher temperature (0.8-2.0): Model considers less likely tokens. More creative, varied, and sometimes unpredictable.
- Default: Usually 1.0 (varies by model)

**When to use what:**
- **Temperature 0.0-0.3**: Factual tasks, code generation, data extraction, when you need consistent outputs
- **Temperature 0.5-0.7**: General-purpose tasks, balanced creativity and consistency
- **Temperature 0.8-1.5**: Creative writing, brainstorming, when variety is desired
- **Temperature 1.5-2.0**: Highly creative tasks, experimental outputs (rarely needed)

**Important note**: Even with temperature 0.0, outputs aren't perfectly deterministic due to model architecture and batching. Don't rely on exact reproducibility.

#### Top_p (Nucleus Sampling) (0.0 to 1.0)

Top_p controls diversity by considering only tokens whose cumulative probability exceeds the threshold. It's an alternative to temperature that can provide more nuanced control.

**How it works:**
- Lower top_p (0.1-0.5): Only considers the most likely tokens. More focused, conservative outputs.
- Higher top_p (0.7-1.0): Considers more tokens. More diverse, creative outputs.
- Default: Usually 1.0 (no filtering)

**Top_p vs Temperature:**
- **Temperature**: Affects all tokens uniformly by scaling probabilities
- **Top_p**: Filters tokens by cumulative probability, more adaptive
- **Recommendation**: Use temperature for most cases, use top_p when you need fine-grained control

**When to use top_p:**
- You want to limit vocabulary to top-N likely tokens
- You need more control than temperature provides
- You're working with models that respond better to top_p

**Note**: Don't use temperature and top_p together unless you know what you're doing. They interact in complex ways. Use one or the other.

#### Max Tokens

Maximum number of tokens the model can generate in its response. This is a hard limit that prevents runaway generation.

**Why it matters:**
- Prevents unexpectedly long outputs (saves tokens and cost)
- Ensures predictable response times
- Controls output length for parsing/processing
- Critical for production systems

**How to set it:**
- Estimate expected output length (in tokens, not words)
- Add 10-20% buffer for safety
- Consider your use case: short answers (50-100 tokens), summaries (200-500 tokens), essays (1000+ tokens)
- Be realistic: too low truncates responses, too high wastes tokens

**Example calculations:**
- 1 token ≈ 0.75 words
- 100 tokens ≈ 75 words ≈ 1-2 paragraphs
- 500 tokens ≈ 375 words ≈ 1-2 pages
- 1000 tokens ≈ 750 words ≈ 2-3 pages

#### Stop Sequences

Text sequences that cause the model to stop generating. Useful for controlling output format and structure.

**How it works:**
- Model stops when it encounters any stop sequence
- Can specify multiple stop sequences (array)
- Stop sequence text is not included in the output
- Useful for structured outputs, list generation, multi-turn conversations

**Common use cases:**
- Stop at double newline (`\n\n`) for paragraph separation
- Stop at specific markers (`"---"`, `"###"`) for structured formats
- Stop at end-of-sentence markers for single-sentence responses
- Stop at conversation boundaries for chat applications

**Best practices:**
- Choose sequences unlikely to appear mid-output
- Test with various inputs to ensure reliable stopping
- Consider edge cases where stop sequence might not trigger
- Use in combination with max_tokens as a fallback

#### Other Important Parameters

**presence_penalty** (-2.0 to 2.0):
- Penalizes tokens based on whether they've appeared in the text so far
- Positive values encourage new topics, negative values encourage repetition
- Useful for avoiding repetitive outputs or encouraging topic diversity

**frequency_penalty** (-2.0 to 2.0):
- Penalizes tokens based on how frequently they've appeared
- Similar to presence_penalty but based on frequency, not just presence
- Can help reduce repetitive phrases or words

**Note**: These penalties are less commonly used and can have unpredictable effects. Start with temperature and max_tokens before experimenting with penalties.

## Code Examples

### Basic Parameter Usage

Complete examples showing how to use parameters effectively:

```python
from openai import OpenAI
import os

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# Low temperature - deterministic (factual tasks)
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "What is 2+2?"}],
    temperature=0.0,  # Deterministic for factual answers
    max_tokens=50
)
print(response.choices[0].message.content)

# Medium temperature - balanced (general tasks)
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Explain how Python lists work"}],
    temperature=0.5,  # Balanced creativity and consistency
    max_tokens=200
)
print(response.choices[0].message.content)

# High temperature - creative (creative tasks)
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a creative short story opening"}],
    temperature=0.9,  # More varied, creative outputs
    max_tokens=200
)
print(response.choices[0].message.content)
```

### Using Stop Sequences

Control output format with stop sequences:

```python
# Stop at double newline (paragraph boundary)
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a single paragraph about AI:"}],
    stop=["\n\n"],  # Stop at paragraph break
    max_tokens=300
)

# Stop at specific marker (structured output)
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "List three benefits of Python:\n1."}],
    stop=["\n4", "###"],  # Stop at item 4 or markdown header
    max_tokens=200
)

# Stop at conversation boundary
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "user", "content": "Tell me a joke"},
    ],
    stop=["User:", "Human:"],  # Stop if model tries to continue conversation
    max_tokens=150
)
```

### Parameter Presets for Common Tasks

Create reusable parameter configurations:

```python
PARAMETER_PRESETS = {
    "factual": {
        "temperature": 0.0,
        "max_tokens": 500,
    },
    "balanced": {
        "temperature": 0.5,
        "max_tokens": 500,
    },
    "creative": {
        "temperature": 0.9,
        "max_tokens": 1000,
    },
    "code": {
        "temperature": 0.0,
        "max_tokens": 2000,
        "stop": ["\n\n\n"],  # Stop at multiple blank lines
    },
    "summarization": {
        "temperature": 0.3,
        "max_tokens": 300,
    },
    "qa": {
        "temperature": 0.0,
        "max_tokens": 200,
    },
}

def generate_with_preset(prompt: str, preset: str, model: str = "gpt-4o"):
    """Generate with a preset parameter configuration."""
    if preset not in PARAMETER_PRESETS:
        raise ValueError(f"Unknown preset: {preset}")
    
    params = PARAMETER_PRESETS[preset].copy()
    
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        **params
    )
    
    return response.choices[0].message.content

# Usage
code_explanation = generate_with_preset(
    "Explain how Python decorators work",
    preset="code"
)
```

### Using Top_p Instead of Temperature

Example using top_p for fine-grained control:

```python
# Using top_p instead of temperature
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a creative tagline"}],
    top_p=0.9,  # Consider tokens in top 90% probability mass
    max_tokens=50
    # Note: Don't set temperature when using top_p
)
```

## Common Mistakes

#### 1. Temperature too high for factual tasks
Using high temperature (0.8+) for factual questions, code generation, or data extraction leads to inconsistent, sometimes incorrect outputs. For factual tasks, use temperature 0.0-0.3. Save high temperature for creative tasks where variety is desired.

#### 2. Not setting max_tokens
Without max_tokens, the model can generate thousands of tokens, wasting money and making responses hard to parse. Always set max_tokens based on expected output length. A 500-token response costs $0.005 with GPT-4o; an unbounded 5000-token response costs $0.05 (10x more).

#### 3. Not using stop sequences for structured outputs
Stop sequences are essential for controlling output format. Without them, list generation continues indefinitely, structured formats break, and parsing becomes difficult. Use stop sequences like `\n\n`, `"---"`, or custom markers to control where generation stops.

#### 4. Using the same parameters for all tasks
Different tasks need different parameters. Factual Q&A needs temperature 0.0, creative writing needs 0.8-1.0, code generation needs 0.0 with high max_tokens. Don't use a one-size-fits-all approach - tune parameters per use case.

#### 5. Using temperature and top_p together
Temperature and top_p interact in complex ways. Using both simultaneously leads to unpredictable behavior. Pick one: use temperature for most cases, or use top_p when you need fine-grained control. Don't set both unless you've tested the interaction.

#### 6. Setting max_tokens too low
If max_tokens is too low, responses get truncated mid-sentence. Estimate your expected output length and add a buffer (10-20%). Test with real inputs to ensure you're not cutting off important content. It's better to set it slightly high than too low.

#### 7. Assuming temperature 0.0 is perfectly deterministic
Even with temperature 0.0, outputs can vary slightly due to model architecture, batching, and other factors. Don't write code that depends on exact string matches. Use temperature 0.0 for consistency, but still validate outputs rather than assuming they're identical.

#### 8. Not testing parameter settings
Parameters affect outputs significantly. Don't guess - test different settings with your actual use case. What works for one task might not work for another. Create test cases, compare outputs, and choose parameters based on real results, not assumptions.

#### 9. Ignoring token costs when setting max_tokens
Higher max_tokens means higher potential costs. Setting max_tokens to 4000 "just to be safe" means every response could cost $0.04 (GPT-4o output pricing). Be realistic about actual needs. Monitor actual token usage and adjust accordingly.

#### 10. Stop sequences that are too common
If your stop sequence appears naturally in the output, generation stops prematurely. Choose stop sequences that are unlikely to appear in normal text. Test with various inputs to ensure stop sequences work reliably across different scenarios.
