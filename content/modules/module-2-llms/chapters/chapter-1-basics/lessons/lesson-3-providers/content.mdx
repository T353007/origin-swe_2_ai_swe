# Model Providers Comparison

## Overview

Different LLM providers offer different models, pricing, and capabilities. Understanding provider differences helps you choose the right one for your use case.

## Main Content

### Major Providers

#### OpenAI
- **Models**: GPT-4, GPT-4 Turbo, GPT-3.5 Turbo
- **Strengths**: Widely used, good documentation, function calling
- **Pricing**: Pay per token, varies by model
- **Best for**: General use cases, function calling

#### Anthropic
- **Models**: Claude 3 Opus, Sonnet, Haiku
- **Strengths**: Long context windows, safety-focused
- **Pricing**: Competitive, longer context = more cost
- **Best for**: Long documents, safety-critical applications

#### Google
- **Models**: Gemini Pro, Gemini Ultra
- **Strengths**: Multimodal, Google ecosystem integration
- **Pricing**: Competitive
- **Best for**: Google Cloud users, multimodal apps

#### Open Source
- **Models**: Llama, Mistral, Mixtral
- **Strengths**: Self-hosted, no API costs, customizable
- **Cons**: Requires infrastructure, harder to set up
- **Best for**: High volume, data privacy, customization

### Provider Comparison Matrix

| Provider | Context Window | Cost | Function Calling | Best For |
|----------|---------------|------|------------------|----------|
| OpenAI GPT-4 | 8K-128K | High | ✅ Excellent | General use |
| Anthropic Claude | 200K | Medium | ✅ Good | Long context |
| Google Gemini | 32K | Medium | ✅ Good | Multimodal |
| Open Source | Variable | Low* | Varies | High volume |

*Low cost but requires infrastructure

### Choosing a Provider

**Factors to consider:**
- **Latency requirements**: Some providers are faster
- **Context window needs**: Long documents need large windows
- **Budget**: Cost varies significantly
- **Features needed**: Function calling, multimodal, etc.
- **Vendor lock-in**: Consider abstraction layers

## Code Examples

Provider abstraction layer:

```python
from abc import ABC, abstractmethod
from typing import Optional

class LLMProvider(ABC):
    @abstractmethod
    def complete(self, prompt: str, **kwargs) -> str:
        pass

class OpenAIProvider(LLMProvider):
    def __init__(self, api_key: str):
        from openai import OpenAI
        self.client = OpenAI(api_key=api_key)
    
    def complete(self, prompt: str, model: str = "gpt-4", **kwargs) -> str:
        response = self.client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": prompt}],
            **kwargs
        )
        return response.choices[0].message.content

class AnthropicProvider(LLMProvider):
    def __init__(self, api_key: str):
        import anthropic
        self.client = anthropic.Anthropic(api_key=api_key)
    
    def complete(self, prompt: str, model: str = "claude-3-opus-20240229", **kwargs) -> str:
        response = self.client.messages.create(
            model=model,
            max_tokens=1024,
            messages=[{"role": "user", "content": prompt}],
            **kwargs
        )
        return response.content[0].text

# Usage with abstraction
provider = OpenAIProvider(os.getenv("OPENAI_API_KEY"))
# Or: provider = AnthropicProvider(os.getenv("ANTHROPIC_API_KEY"))

result = provider.complete("Hello!")
```

## Common Mistakes

1. **Vendor lock-in**: Hard to switch providers later
2. **Ignoring costs**: Different providers have different pricing
3. **Not testing alternatives**: Best provider may vary by use case
4. **No fallback**: Single provider failures break system
