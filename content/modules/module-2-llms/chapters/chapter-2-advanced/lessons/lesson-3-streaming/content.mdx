# Streaming Responses

> **💡** *Streaming LLM responses is like watching a movie instead of reading the script: you get the content as it's being created, not after everything is done. Without streaming, users stare at a loading spinner for 10 seconds wondering if the AI is even working. With streaming, they see text appearing word-by-word, which feels instant even though it takes the same total time. The difference? Perceived performance. Users don't care about total time if they feel like something is happening.*

## Overview

Streaming allows LLM responses to be sent incrementally as they're generated, dramatically improving perceived latency and user experience in production applications. Instead of waiting for the complete response, users see tokens appear in real-time, making the application feel faster and more responsive.

In 2024-2025, streaming has become standard for production AI applications. Models like GPT-4o, GPT-5.2, and Claude 4.5 all support streaming. For interactive applications like chatbots, assistants, and real-time systems, streaming is essential. This lesson covers how to implement streaming effectively, handle errors, build streaming APIs, and measure performance improvements.

## Main Content

### Why Streaming?

**Without Streaming:**
- User waits 5-10 seconds for complete response
- Bad user experience
- No progress indication
- Higher time-to-first-token

**With Streaming:**
- First token arrives in less than 1 second
- Immediate feedback to user
- Better perceived performance
- Can cancel if needed

### How Streaming Works

Streaming sends tokens incrementally as the model generates them:

1. **Request sent**: API call with `stream=True`
2. **Stream starts**: Server begins generating tokens
3. **Chunks arrive**: Each chunk contains one or more tokens
4. **Process incrementally**: Display tokens as they arrive
5. **Stream completes**: Final chunk signals completion

**Key differences from non-streaming:**
- Non-streaming: Wait for all tokens, then return complete response
- Streaming: Receive tokens incrementally, process as they arrive
- Time-to-first-token: Much faster with streaming
- Total time: Similar, but user perceives it as faster

### Basic Streaming

Simple streaming implementation:

```python
from openai import OpenAI
import sys
import os

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def stream_completion(prompt: str, model: str = "gpt-4o"):
    """Stream LLM response token by token."""
    stream = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        stream=True  # Enable streaming
    )
    
    for chunk in stream:
        if chunk.choices[0].delta.content:
            content = chunk.choices[0].delta.content
            print(content, end="", flush=True)  # Print immediately
    
    print()  # New line at end

# Usage
stream_completion("Explain how RAG works")
```

**Key points:**
- `stream=True` enables streaming mode
- Chunks arrive incrementally
- `chunk.choices[0].delta.content` contains new tokens
- Use `flush=True` to display tokens immediately
- Handle empty chunks (when delta.content is None)

### Streaming with Error Handling

Robust streaming with error handling and timeout:

```python
from typing import Iterator, Optional
import time
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def stream_safely(
    prompt: str,
    model: str = "gpt-4o",
    timeout: float = 30.0,
    max_tokens: Optional[int] = None
) -> Iterator[str]:
    """
    Stream with proper error handling.
    
    Yields:
        Content chunks as they arrive
    """
    try:
        stream = client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": prompt}],
            stream=True,
            timeout=timeout,
            max_tokens=max_tokens
        )
        
        start_time = time.time()
        chunk_count = 0
        
        for chunk in stream:
            # Check timeout
            if time.time() - start_time > timeout:
                logger.warning("Stream timeout exceeded")
                break
            
            if chunk.choices[0].delta.content:
                content = chunk.choices[0].delta.content
                chunk_count += 1
                yield content
        
        logger.info(f"Stream completed: {chunk_count} chunks")
        
    except Exception as e:
        logger.error(f"Streaming error: {e}")
        raise Exception(f"Streaming failed: {e}")

# Usage
for chunk in stream_safely("Explain machine learning"):
    print(chunk, end="", flush=True)
```

### Generator Pattern for Streaming

Use Python generators for clean streaming interfaces:

```python
from typing import Iterator

def stream_generator(prompt: str, model: str = "gpt-4o") -> Iterator[str]:
    """
    Generator that yields streaming tokens.
    
    Benefits:
    - Memory efficient (doesn't store full response)
    - Clean interface
    - Easy to integrate with async code
    """
    stream = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        stream=True
    )
    
    for chunk in stream:
        delta = chunk.choices[0].delta
        if delta.content:
            yield delta.content

# Usage - memory efficient
for token in stream_generator("Long response here..."):
    process_token(token)  # Process each token without storing all
```

### Streaming with Full Response Tracking

Track the complete response while streaming:

```python
def stream_with_tracking(prompt: str, model: str = "gpt-4o") -> tuple[Iterator[str], str]:
    """
    Stream response and return both generator and full text.
    
    Returns:
        Tuple of (token_generator, full_response)
    """
    stream = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        stream=True
    )
    
    full_response = ""
    
    def token_generator():
        nonlocal full_response
        for chunk in stream:
            if chunk.choices[0].delta.content:
                content = chunk.choices[0].delta.content
                full_response += content
                yield content
    
    return token_generator(), full_response

# Usage
tokens, full_text = stream_with_tracking("Explain RAG")
for token in tokens:
    print(token, end="", flush=True)
print(f"\n\nFull response: {full_text}")
```

### Server-Sent Events (SSE) for Web APIs

Stream to web clients using Server-Sent Events:

```python
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
import json
import os
from openai import OpenAI

app = FastAPI()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

@app.post("/api/stream")
async def stream_endpoint(request: Request):
    """Stream LLM response as Server-Sent Events."""
    data = await request.json()
    prompt = data.get("prompt", "")
    model = data.get("model", "gpt-4o")
    
    async def generate():
        """Generate SSE stream from LLM."""
        try:
            stream = client.chat.completions.create(
                model=model,
                messages=[{"role": "user", "content": prompt}],
                stream=True
            )
            
            for chunk in stream:
                if chunk.choices[0].delta.content:
                    content = chunk.choices[0].delta.content
                    # Format as SSE (Server-Sent Events)
                    yield f"data: {json.dumps({'content': content})}\n\n"
            
            # Signal completion
            yield "data: [DONE]\n\n"
            
        except Exception as e:
            # Send error as SSE
            yield f"data: {json.dumps({'error': str(e)})}\n\n"
    
    return StreamingResponse(
        generate(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no"  # Disable buffering in nginx
        }
    )
```

### WebSocket Streaming

For bidirectional communication, use WebSockets:

```python
from fastapi import FastAPI, WebSocket
import json
import asyncio

app = FastAPI()

@app.websocket("/ws/stream")
async def websocket_stream(websocket: WebSocket):
    """Stream LLM response via WebSocket."""
    await websocket.accept()
    
    try:
        # Receive prompt from client
        data = await websocket.receive_json()
        prompt = data.get("prompt", "")
        
        # Create streaming request
        stream = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            stream=True
        )
        
        # Send tokens incrementally
        for chunk in stream:
            if chunk.choices[0].delta.content:
                content = chunk.choices[0].delta.content
                await websocket.send_json({"type": "token", "content": content})
        
        # Signal completion
        await websocket.send_json({"type": "done"})
        
    except Exception as e:
        await websocket.send_json({"type": "error", "message": str(e)})
    finally:
        await websocket.close()
```

## Code Examples

### Production-Ready Streaming Class

Complete streaming implementation with error handling, timeouts, and metrics:

```python
from typing import Iterator, Optional, Dict, Any
from openai import OpenAI
import time
import logging
from datetime import datetime

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

class StreamingLLM:
    """Production-ready streaming LLM client."""
    
    def __init__(
        self,
        model: str = "gpt-4o",
        api_key: Optional[str] = None,
        timeout: float = 30.0
    ):
        self.client = OpenAI(api_key=api_key or os.getenv("OPENAI_API_KEY"))
        self.model = model
        self.timeout = timeout
        self.stats = {
            "total_requests": 0,
            "total_tokens": 0,
            "total_time": 0.0,
            "avg_time_to_first_token": 0.0
        }
    
    def stream(
        self,
        prompt: str,
        max_tokens: Optional[int] = None,
        temperature: float = 0.7,
        **kwargs
    ) -> Iterator[str]:
        """
        Stream response tokens.
        
        Yields:
            Content chunks as they arrive
        """
        self.stats["total_requests"] += 1
        start_time = time.time()
        first_token_time = None
        token_count = 0
        
        try:
            stream = self.client.chat.completions.create(
                model=self.model,
                messages=[{"role": "user", "content": prompt}],
                stream=True,
                timeout=self.timeout,
                max_tokens=max_tokens,
                temperature=temperature,
                **kwargs
            )
            
            for chunk in stream:
                delta = chunk.choices[0].delta
                
                if delta.content:
                    # Track time to first token
                    if first_token_time is None:
                        first_token_time = time.time()
                        time_to_first = first_token_time - start_time
                        self.stats["avg_time_to_first_token"] = (
                            (self.stats["avg_time_to_first_token"] * (self.stats["total_requests"] - 1) + time_to_first) /
                            self.stats["total_requests"]
                        )
                    
                    content = delta.content
                    token_count += len(content.split())  # Approximate token count
                    yield content
            
            # Update statistics
            total_time = time.time() - start_time
            self.stats["total_time"] += total_time
            self.stats["total_tokens"] += token_count
            
        except Exception as e:
            logger.error(f"Streaming error: {e}")
            raise
    
    def stream_complete(
        self,
        prompt: str,
        **kwargs
    ) -> str:
        """
        Stream and collect full response.
        
        Returns:
            Complete response text
        """
        full_response = ""
        for chunk in self.stream(prompt, **kwargs):
            full_response += chunk
        return full_response
    
    def get_stats(self) -> Dict[str, Any]:
        """Get streaming statistics."""
        avg_time = (
            self.stats["total_time"] / self.stats["total_requests"]
            if self.stats["total_requests"] > 0 else 0
        )
        avg_tokens = (
            self.stats["total_tokens"] / self.stats["total_requests"]
            if self.stats["total_requests"] > 0 else 0
        )
        
        return {
            **self.stats,
            "avg_response_time": avg_time,
            "avg_tokens_per_request": avg_tokens
        }

# Usage
llm = StreamingLLM(model="gpt-4o")

# Stream tokens
for token in llm.stream("Explain how RAG works"):
    print(token, end="", flush=True)

# Get complete response
full_response = llm.stream_complete("What is machine learning?")
print(full_response)

# Check statistics
stats = llm.get_stats()
print(f"Average time to first token: {stats['avg_time_to_first_token']:.2f}s")
```

### Async Streaming

For async applications, use async streaming:

```python
import asyncio
from openai import AsyncOpenAI

async_client = AsyncOpenAI(api_key=os.getenv("OPENAI_API_KEY"))

async def stream_async(prompt: str, model: str = "gpt-4o"):
    """Stream response asynchronously."""
    stream = await async_client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        stream=True
    )
    
    async for chunk in stream:
        if chunk.choices[0].delta.content:
            content = chunk.choices[0].delta.content
            yield content

# Usage in async function
async def main():
    async for token in stream_async("Explain async programming"):
        print(token, end="", flush=True)

asyncio.run(main())
```

## Common Mistakes

#### 1. Not handling stream errors
Network issues, API errors, and connection problems can interrupt streaming. Without error handling, streams fail silently or crash your application. Always wrap streaming code in try/except blocks, handle exceptions gracefully, and provide feedback to users when streams fail.

#### 2. No timeout handling
Streams can hang indefinitely if the model takes too long or if there's a network issue. Without timeouts, users wait forever and resources are wasted. Always set reasonable timeouts (e.g., 30-60 seconds) and handle timeout exceptions appropriately.

#### 3. Not flushing output
Without `flush=True` in print statements, tokens are buffered and don't appear immediately, defeating the purpose of streaming. Always use `flush=True` when displaying streamed content, or use unbuffered I/O for immediate display.

#### 4. Ignoring empty chunks
Not all chunks contain content. Some chunks are metadata, some signal completion, and some have empty delta.content. Always check if `delta.content` exists before processing. Failing to handle empty chunks can cause errors or missing content.

#### 5. No cancellation support
Long-running streams consume resources and API costs. Without cancellation, users can't stop expensive requests. Implement cancellation mechanisms (signal handling, user-initiated stops) to allow users to abort streaming requests when needed.

#### 6. Not tracking full response
Some applications need both streaming tokens and the complete response. If you only stream without tracking, you can't access the full text later. Track the complete response while streaming if your application needs it for storage, analysis, or further processing.

#### 7. Blocking the event loop
In async applications, blocking I/O during streaming blocks the entire event loop. Use async streaming APIs (`AsyncOpenAI`) instead of synchronous ones. For FastAPI/async frameworks, use async generators and async streaming properly.

#### 8. Not measuring performance
You can't optimize what you don't measure. Without tracking metrics (time-to-first-token, total time, token count), you don't know if streaming is actually improving performance. Track metrics and compare streaming vs non-streaming performance.

#### 9. Inefficient chunk processing
Processing each tiny chunk individually can be inefficient. While you should display tokens immediately, consider batching small processing operations. However, don't batch display: users need to see tokens as they arrive for the streaming benefit.

#### 10. Not handling stream completion
Streams don't always signal completion clearly. The final chunk might be empty or contain metadata. Always handle stream completion properly: track when streams end, handle final chunks, and signal completion to users/clients appropriately.
