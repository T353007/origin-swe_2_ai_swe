# Basic RAG Implementation

> **💡** *Building your first RAG system is like assembling a pizza from scratch: you need the right ingredients (documents), cut them properly (chunking), store them where you can find them (vector database), then combine them when someone orders (retrieve and generate). Get any step wrong and you end up with a mess: documents that don't make sense, chunks that can't be found, or answers that hallucinate instead of using your ingredients. But do it right, and you've got a system that can answer questions using your own knowledge base, not just what the LLM learned during training.*

## Overview

This lesson brings everything together: you'll build a complete RAG system from scratch, combining document loading, chunking, embedding, vector storage, retrieval, and generation. This is where theory becomes practice, and you'll have a working RAG system by the end.

In 2024-2025, building RAG systems has become more accessible with frameworks like LangChain and LlamaIndex, but understanding the fundamentals is still crucial. This lesson covers both framework-based and custom implementations, so you understand what's happening under the hood and can build production-ready systems.

## Main Content

### RAG Pipeline Overview

A complete RAG system integrates multiple components into a cohesive pipeline:

#### 1. Document Loading
- Load documents from various sources (files, APIs, databases)
- Support multiple formats (PDF, markdown, text, HTML, etc.)
- Extract text and metadata
- Handle errors and edge cases

#### 2. Text Chunking
- Split documents into smaller, manageable chunks
- Choose appropriate chunk size and overlap
- Preserve metadata during chunking
- Handle different document structures

#### 3. Embedding Generation
- Convert chunks to embedding vectors
- Use appropriate embedding model
- Batch processing for efficiency
- Cache embeddings to avoid regeneration

#### 4. Vector Storage
- Store embeddings in vector database
- Include original text and metadata
- Enable efficient similarity search
- Persist data for reuse

#### 5. Retrieval
- Convert query to embedding
- Search for similar chunks
- Rank and filter results
- Return top-k most relevant chunks

#### 6. Generation
- Construct prompt with retrieved context
- Generate answer using LLM
- Include source citations
- Handle edge cases (no results, errors)

#### 7. Response Assembly
- Format answer appropriately
- Include source information
- Provide metadata (confidence, sources, etc.)
- Handle errors gracefully

**The Complete Flow:**

```
Documents → Load → Chunk → Embed → Store
                                        ↓
Query → Embed → Search → Retrieve → Generate → Answer
```

### Complete RAG Implementation with LangChain

LangChain provides high-level abstractions for building RAG systems quickly:

```python
from langchain_community.document_loaders import TextLoader, DirectoryLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import Chroma
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain.chains import RetrievalQA
from langchain_core.prompts import ChatPromptTemplate
import os

# Step 1: Load documents
loader = DirectoryLoader(
    "./documents",
    glob="**/*.txt",
    loader_cls=TextLoader
)
documents = loader.load()

print(f"Loaded {len(documents)} documents")

# Step 2: Split documents into chunks
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    length_function=len,
    separators=["\n\n", "\n", ". ", " ", ""]
)
chunks = text_splitter.split_documents(documents)

print(f"Created {len(chunks)} chunks")

# Step 3: Create embeddings and vector store
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"  # Cost-effective embedding model
)

vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db"  # Persist for reuse
)

print("Vector store created and persisted")

# Step 4: Create retrieval chain
llm = ChatOpenAI(
    model="gpt-4o",  # Current model (2024-2025)
    temperature=0
)

retriever = vectorstore.as_retriever(
    search_kwargs={"k": 3}  # Retrieve top 3 chunks
)

# Create prompt template
prompt = ChatPromptTemplate.from_template("""
You are a helpful assistant that answers questions based on the provided context.

Context:
{context}

Question: {input}

Answer the question based only on the provided context. If the context doesn't contain enough information to answer the question, say so.

Answer:""")

# Create QA chain
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",  # Put all context in one prompt
    retriever=retriever,
    return_source_documents=True,
    chain_type_kwargs={"prompt": prompt}
)

# Step 5: Query the RAG system
result = qa_chain.invoke({"query": "What is RAG?"})

print(f"Question: {result['query']}")
print(f"Answer: {result['result']}")
print(f"\nSources ({len(result['source_documents'])}):")
for i, doc in enumerate(result['source_documents'], 1):
    print(f"  {i}. {doc.metadata.get('source', 'Unknown')}")
    print(f"     {doc.page_content[:100]}...")
```

**Key Components Explained:**

- **DirectoryLoader**: Loads multiple documents from a directory
- **RecursiveCharacterTextSplitter**: Splits documents intelligently, respecting structure
- **Chroma**: Vector database for storing and searching embeddings
- **OpenAIEmbeddings**: Generates embeddings using OpenAI's models
- **RetrievalQA**: LangChain's high-level RAG chain that combines retrieval and generation
- **chain_type="stuff"**: Puts all retrieved context in a single prompt (simple, works well for small contexts)

### Custom RAG Implementation (From Scratch)

Building RAG without frameworks gives you full control and helps you understand what's happening:

```python
from openai import OpenAI
import chromadb
from chromadb.config import Settings
from typing import List, Dict, Any, Optional
import os

class CustomRAG:
    """Custom RAG implementation for full control."""
    
    def __init__(
        self,
        embedding_model: str = "text-embedding-3-small",
        llm_model: str = "gpt-4o",
        persist_directory: str = "./rag_db"
    ):
        self.llm_client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
        self.embedding_model = embedding_model
        self.llm_model = llm_model
        
        # Initialize Chroma
        self.chroma_client = chromadb.PersistentClient(
            path=persist_directory
        )
        self.collection = self.chroma_client.get_or_create_collection(
            name="documents",
            metadata={"description": "RAG document collection"}
        )
    
    def index_documents(
        self,
        documents: List[str],
        doc_ids: List[str],
        metadatas: Optional[List[Dict[str, Any]]] = None
    ):
        """
        Index documents in vector store.
        
        Args:
            documents: List of document texts
            doc_ids: List of document IDs
            metadatas: Optional list of metadata dicts
        """
        # Generate embeddings in batch
        response = self.llm_client.embeddings.create(
            input=documents,
            model=self.embedding_model
        )
        embeddings = [item.embedding for item in response.data]
        
        # Prepare metadatas
        if metadatas is None:
            metadatas = [{}] * len(documents)
        
        # Store in Chroma
        self.collection.add(
            embeddings=embeddings,
            documents=documents,
            ids=doc_ids,
            metadatas=metadatas
        )
        
        print(f"Indexed {len(documents)} documents")
    
    def retrieve(self, query: str, k: int = 3) -> List[Dict[str, Any]]:
        """
        Retrieve relevant document chunks.
        
        Returns:
            List of dicts with 'text', 'metadata', 'distance'
        """
        # Get query embedding
        response = self.llm_client.embeddings.create(
            input=[query],
            model=self.embedding_model
        )
        query_embedding = response.data[0].embedding
        
        # Search
        results = self.collection.query(
            query_embeddings=[query_embedding],
            n_results=k,
            include=["documents", "metadatas", "distances"]
        )
        
        # Format results
        retrieved = []
        for i in range(len(results["ids"][0])):
            retrieved.append({
                "text": results["documents"][0][i],
                "metadata": results["metadatas"][0][i] if results["metadatas"] else {},
                "distance": results["distances"][0][i],
                "id": results["ids"][0][i]
            })
        
        return retrieved
    
    def generate(self, query: str, context_chunks: List[Dict[str, Any]]) -> str:
        """
        Generate answer using retrieved context.
        
        Args:
            query: User's question
            context_chunks: Retrieved document chunks
        
        Returns:
            Generated answer
        """
        # Build context with citations
        context_parts = []
        for i, chunk in enumerate(context_chunks, 1):
            source = chunk["metadata"].get("source", "Unknown")
            context_parts.append(f"[{i}] {chunk['text']} (Source: {source})")
        
        context_text = "\n\n".join(context_parts)
        
        # Construct prompt
        prompt = f"""You are a helpful assistant that answers questions based on the provided context.

Context:
{context_text}

Question: {query}

Answer the question based only on the provided context. If the context doesn't contain enough information to answer the question, say so. When referencing information from the context, cite the source using [1], [2], etc.

Answer:"""
        
        # Generate answer
        response = self.llm_client.chat.completions.create(
            model=self.llm_model,
            messages=[{"role": "user", "content": prompt}],
            temperature=0
        )
        
        return response.choices[0].message.content
    
    def query(self, question: str, k: int = 3) -> Dict[str, Any]:
        """
        Complete RAG query: retrieve and generate.
        
        Returns:
            Dict with 'question', 'answer', 'sources', 'retrieved_chunks'
        """
        # Retrieve relevant chunks
        retrieved = self.retrieve(question, k)
        
        if not retrieved:
            return {
                "question": question,
                "answer": "I couldn't find any relevant information to answer this question.",
                "sources": [],
                "retrieved_chunks": []
            }
        
        # Generate answer
        answer = self.generate(question, retrieved)
        
        return {
            "question": question,
            "answer": answer,
            "sources": [chunk["metadata"] for chunk in retrieved],
            "retrieved_chunks": retrieved
        }

# Usage
rag = CustomRAG()

# Index documents
rag.index_documents(
    documents=[
        "RAG (Retrieval-Augmented Generation) combines information retrieval with language generation...",
        "Vector databases store embeddings and enable efficient similarity search...",
    ],
    doc_ids=["doc1", "doc2"],
    metadatas=[
        {"source": "rag_intro.md", "category": "fundamentals"},
        {"source": "vector_dbs.md", "category": "fundamentals"}
    ]
)

# Query
result = rag.query("What is RAG?")
print(f"Question: {result['question']}")
print(f"Answer: {result['answer']}")
print(f"Sources: {len(result['sources'])} documents")
```

### Production-Ready RAG System

Complete RAG system with error handling, source citations, and best practices:

```python
from openai import OpenAI
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import Chroma
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from typing import List, Dict, Any, Optional
import os
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

class ProductionRAG:
    """Production-ready RAG system with error handling and best practices."""
    
    def __init__(
        self,
        embedding_model: str = "text-embedding-3-small",
        llm_model: str = "gpt-4o",
        chunk_size: int = 1000,
        chunk_overlap: int = 200,
        persist_directory: str = "./rag_db",
        k: int = 3
    ):
        self.llm_client = ChatOpenAI(
            model=llm_model,
            temperature=0,
            api_key=os.getenv("OPENAI_API_KEY")
        )
        self.embeddings = OpenAIEmbeddings(
            model=embedding_model,
            api_key=os.getenv("OPENAI_API_KEY")
        )
        self.text_splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size,
            chunk_overlap=chunk_overlap
        )
        self.k = k
        
        # Initialize vector store
        self.vectorstore = Chroma(
            persist_directory=persist_directory,
            embedding_function=self.embeddings
        )
    
    def index_documents(
        self,
        documents: List[str],
        metadatas: Optional[List[Dict[str, Any]]] = None
    ):
        """Index documents with chunking and metadata."""
        try:
            # Split documents
            all_chunks = []
            all_metadatas = []
            
            for i, doc_text in enumerate(documents):
                chunks = self.text_splitter.split_text(doc_text)
                
                base_metadata = metadatas[i] if metadatas else {}
                for j, chunk in enumerate(chunks):
                    chunk_metadata = {
                        **base_metadata,
                        "chunk_index": j,
                        "total_chunks": len(chunks),
                        "doc_index": i
                    }
                    all_chunks.append(chunk)
                    all_metadatas.append(chunk_metadata)
            
            # Add to vector store
            self.vectorstore.add_texts(
                texts=all_chunks,
                metadatas=all_metadatas
            )
            
            logger.info(f"Indexed {len(documents)} documents, created {len(all_chunks)} chunks")
            
        except Exception as e:
            logger.error(f"Error indexing documents: {e}")
            raise
    
    def query(
        self,
        question: str,
        k: Optional[int] = None,
        include_sources: bool = True
    ) -> Dict[str, Any]:
        """
        Query RAG system with error handling.
        
        Returns:
            Dict with 'answer', 'sources', 'retrieved_chunks'
        """
        k = k or self.k
        
        try:
            # Retrieve relevant chunks
            retrieved_docs = self.vectorstore.similarity_search(
                question,
                k=k
            )
            
            if not retrieved_docs:
                return {
                    "answer": "I couldn't find any relevant information to answer this question.",
                    "sources": [],
                    "retrieved_chunks": []
                }
            
            # Build context with citations
            context_parts = []
            for i, doc in enumerate(retrieved_docs, 1):
                source = doc.metadata.get("source", "Unknown")
                context_parts.append(
                    f"[{i}] {doc.page_content}\n(Source: {source})"
                )
            
            context = "\n\n".join(context_parts)
            
            # Construct prompt
            prompt = f"""You are a helpful assistant that answers questions based on the provided context.

Context:
{context}

Question: {question}

Answer the question based only on the provided context. If the context doesn't contain enough information to answer the question, say so. When referencing information from the context, cite the source using [1], [2], etc.

Answer:"""
            
            # Generate answer
            response = self.llm_client.invoke(prompt)
            answer = response.content if hasattr(response, 'content') else str(response)
            
            # Prepare sources
            sources = [doc.metadata for doc in retrieved_docs] if include_sources else []
            
            return {
                "answer": answer,
                "sources": sources,
                "retrieved_chunks": [
                    {
                        "text": doc.page_content,
                        "metadata": doc.metadata,
                        "score": getattr(doc, 'score', None)
                    }
                    for doc in retrieved_docs
                ]
            }
            
        except Exception as e:
            logger.error(f"Error querying RAG system: {e}")
            return {
                "answer": f"An error occurred while processing your question: {str(e)}",
                "sources": [],
                "retrieved_chunks": []
            }

# Usage
rag = ProductionRAG()

# Index documents
documents = [
    "RAG combines retrieval and generation...",
    "Vector databases enable similarity search...",
]

rag.index_documents(
    documents,
    metadatas=[
        {"source": "intro.md", "category": "fundamentals"},
        {"source": "vectordb.md", "category": "fundamentals"}
    ]
)

# Query
result = rag.query("What is RAG?", k=3)
print(result["answer"])
print(f"\nSources: {len(result['sources'])}")
```

## Common Mistakes

#### 1. Not testing retrieval quality
Deploying RAG without testing retrieval quality leads to poor answers. If retrieval returns irrelevant chunks, even the best LLM can't produce good answers. Always test retrieval: inspect retrieved chunks for sample queries, measure relevance, and iterate on chunking/embedding strategies. Retrieval quality is the foundation of RAG performance.

#### 2. Context too long
Including too much retrieved context exceeds token limits, causing truncation or errors. Large contexts also increase costs and may confuse the LLM with too much information. Balance the number of chunks (k) with chunk size to stay within context limits. For GPT-4o (128K context), you can afford more chunks; for smaller contexts, be more selective.

#### 3. No source tracking
Building RAG without source tracking makes it impossible to verify answers, debug issues, or provide citations to users. Always preserve and include metadata (source, page, author, etc.) with chunks. Include source information in responses so users can verify information and explore source documents. Source tracking is essential for trust and debugging.

#### 4. Wrong k value
Choosing the wrong number of chunks (k) hurts performance. Too few chunks (k=1-2) may miss relevant information or lack necessary context. Too many chunks (k=10+) add noise, increase costs, and may confuse the LLM. Start with k=3-5, test different values, and choose based on your use case and context window size.

#### 5. Not handling edge cases
Failing to handle edge cases (no results, errors, empty queries) leads to crashes or poor user experience. Always handle: queries with no matching chunks, network/API errors, empty or invalid queries, very long queries, and malformed responses. Implement graceful error handling and provide meaningful error messages.

#### 6. Ignoring prompt engineering
Using a basic prompt template without optimization reduces answer quality. Prompt structure, instructions, and formatting significantly affect how well the LLM uses retrieved context. Test different prompt templates, include clear instructions, specify how to use citations, and tell the LLM what to do when context is insufficient. Prompt engineering is crucial for RAG quality.

#### 7. No evaluation
Deploying RAG without evaluation means you don't know if it's working well. Without metrics, you can't identify problems, measure improvements, or optimize the system. Implement evaluation from the start: test with sample queries, measure answer quality, track retrieval accuracy, and iterate based on results. You can't improve what you don't measure.

#### 8. Forgetting to persist vector store
Not persisting the vector store means re-indexing documents every time the system restarts. This is slow, expensive, and wasteful. Always configure persistence for production use. Chroma, Pinecone, and other vector databases support persistence. Test that persistence works correctly and that data survives restarts.

#### 9. Not chunking properly
Using poor chunking strategies creates chunks that don't make semantic sense, reducing retrieval quality. Chunks that are too large or too small, or that ignore document structure, hurt RAG performance. Invest time in chunking: test different strategies, respect document structure, and choose appropriate chunk sizes. Good chunking is fundamental to good RAG.

#### 10. Using outdated models or APIs
Using outdated models (GPT-3.5, text-embedding-ada-002) or old API patterns reduces quality and increases costs. Stay current: use GPT-4o or GPT-5.2, text-embedding-3-small or text-embedding-3-large, and current API patterns. Outdated models are slower, less capable, and may cost more. Always use the latest stable models for production.
