# CI/CD for AI Systems

> **💡** CI/CD for AI systems is like CI/CD for regular software, except your tests are probabilistic, your prompts are code that needs versioning, and a deployment that 'works' might still produce slightly different outputs each time. It's CI/CD, but you're testing a system that's designed to be non-deterministic while still catching regressions. The irony is not lost on anyone." - AI Engineering Best Practice

## Overview

CI/CD for AI systems requires adapting traditional CI/CD patterns to handle non-deterministic outputs, prompt versioning, model management, and evaluation-based testing. This lesson covers CI/CD patterns specifically designed for AI applications.

Traditional CI/CD assumes deterministic behavior - same input produces same output. AI systems break this assumption, requiring evaluation-based testing, confidence thresholds, and probabilistic quality checks. The goal is the same (reliable, automated deployments) but the methods differ.

## CI/CD Challenges for AI Systems

AI systems present unique challenges for CI/CD pipelines:

### 1. Non-Deterministic Outputs

AI outputs vary even with identical inputs (temperature > 0, probabilistic sampling).

**Challenges:**
- Can't use exact match tests
- Need confidence thresholds
- Must handle variance
- Quality is probabilistic

**Solutions:**
- Use evaluation frameworks (semantic similarity, LLM-as-judge)
- Set confidence thresholds
- Average multiple runs
- Test score distributions

### 2. Prompt as Code

Prompts are code that needs versioning, testing, and deployment.

**Challenges:**
- Prompts change frequently
- Need version control
- Must test prompt changes
- Versioning strategy needed

**Solutions:**
- Version prompts explicitly
- Test prompt changes
- A/B test prompts
- Track prompt performance

### 3. Model Management

Models, embeddings, and configurations need versioning.

**Challenges:**
- Model versions change
- Embedding models affect retrieval
- Configuration changes impact behavior
- Need to track what's deployed

**Solutions:**
- Version model configurations
- Test model changes
- Track model performance
- Support model rollback

### 4. Evaluation-Based Testing

Testing requires evaluations, not unit tests.

**Challenges:**
- Evaluations can be expensive (LLM calls)
- Evaluations can be slow
- Need to balance thoroughness with speed
- Flaky evaluations

**Solutions:**
- Use fast evaluations for CI
- Run comprehensive evaluations separately
- Cache evaluation results
- Handle flakiness explicitly

## Testing Strategies

Different testing strategies for different stages of CI/CD.

### 1. Unit Tests (Fast, Deterministic)

Test deterministic components (parsing, validation, utilities).

```python
# tests/unit/test_parsing.py
import pytest
from rag_system import parse_query, validate_input

def test_parse_query():
    """Test query parsing (deterministic)."""
    result = parse_query("What is RAG?")
    assert result == {"query": "What is RAG?", "type": "question"}

def test_validate_input():
    """Test input validation (deterministic)."""
    assert validate_input("valid query") == True
    assert validate_input("") == False
    assert validate_input("a" * 10000) == False  # Too long
```

### 2. Integration Tests (Medium Speed)

Test component interactions with deterministic or controlled randomness.

```python
# tests/integration/test_retrieval.py
import pytest
from rag_system import RetrievalSystem

def test_retrieval_consistency():
    """Test retrieval returns consistent results."""
    system = RetrievalSystem()
    query = "What is RAG?"
    
    # Retrieval should be deterministic (same embeddings)
    results1 = system.retrieve(query, top_k=5)
    results2 = system.retrieve(query, top_k=5)
    
    assert results1 == results2  # Should be identical

def test_chunking():
    """Test document chunking."""
    system = RetrievalSystem()
    document = "Long document..." * 100
    
    chunks = system.chunk_document(document, chunk_size=500)
    
    assert len(chunks) > 0
    assert all(len(chunk) <= 500 for chunk in chunks)
```

### 3. Evaluation Tests (Slower, Probabilistic)

Test end-to-end system with evaluation frameworks.

```python
# tests/evaluation/test_rag_system.py
import pytest
from eval_framework import EvalFramework
from rag_system import RAGSystem
```

## Prompt Versioning

Version prompts like code - track changes, test impact, deploy safely.

### Prompt Versioning Strategy

```python
# prompts/versioned_prompts.py
from dataclasses import dataclass
from typing import Dict, Optional
from datetime import datetime

@dataclass
class PromptVersion:
    """Versioned prompt with metadata."""
    version: str
    prompt: str
    description: str
    created_at: str
    author: str
    performance_metrics: Optional[Dict] = None

class PromptRegistry:
    """Registry for versioned prompts."""
    
    def __init__(self):
        self.prompts: Dict[str, Dict[str, PromptVersion]] = {}
    
    def register(
        self,
        prompt_name: str,
        version: str,
        prompt: str,
        description: str,
        author: str
    ):
        """Register a new prompt version."""
        if prompt_name not in self.prompts:
            self.prompts[prompt_name] = {}
        
        self.prompts[prompt_name][version] = PromptVersion(
            version=version,
            prompt=prompt,
            description=description,
            created_at=datetime.now().isoformat(),
            author=author
        )
    
    def get(self, prompt_name: str, version: str = "latest") -> str:
        """Get a prompt by name and version."""
        if prompt_name not in self.prompts:
            raise ValueError(f"Prompt '{prompt_name}' not found")
        
        if version == "latest":
            versions = sorted(self.prompts[prompt_name].keys(), reverse=True)
            version = versions[0] if versions else None
        
        if version not in self.prompts[prompt_name]:
            raise ValueError(f"Version '{version}' not found for '{prompt_name}'")
        
        return self.prompts[prompt_name][version].prompt
    
    def list_versions(self, prompt_name: str) -> list:
        """List all versions of a prompt."""
        if prompt_name not in self.prompts:
            return []
        return sorted(self.prompts[prompt_name].keys(), reverse=True)

# Usage
registry = PromptRegistry()

registry.register(
    prompt_name="rag_system_prompt",
    version="v1",
    prompt="You are a helpful assistant. Answer questions based on the following context:\n\n{context}\n\nQuestion: {question}",
    description="Initial RAG prompt",
    author="team"
)

registry.register(
    prompt_name="rag_system_prompt",
    version="v2",
    prompt="You are an expert assistant. Use the following context to provide accurate, comprehensive answers:\n\nContext:\n{context}\n\nQuestion: {question}\n\nAnswer:",
    description="Improved prompt with better structure",
    author="team"
)

# Get prompt
current_prompt = registry.get("rag_system_prompt", version="v2")
```

### Testing Prompt Changes

Test prompt changes before deployment:

```python
# scripts/test_prompt_change.py
from prompt_registry import PromptRegistry
from eval_framework import EvalFramework
import sys

def test_prompt_change(old_version: str, new_version: str):
    """Test if new prompt version is better than old."""
    registry = PromptRegistry()
    framework = EvalFramework()
    framework.load_dataset("test_datasets/rag_basic.json")
    
    # Create system with old prompt
    old_prompt = registry.get("rag_system_prompt", old_version)
    old_system = RAGSystem(prompt=old_prompt)
    old_results = framework.evaluate(old_system.query)
    
    # Create system with new prompt
    new_prompt = registry.get("rag_system_prompt", new_version)
    new_system = RAGSystem(prompt=new_prompt)
    new_results = framework.evaluate(new_system.query)
    
    # Compare results
    improvement = new_results["pass_rate"] - old_results["pass_rate"]
    
    print(f"Old version ({old_version}): {old_results['pass_rate']:.2%}")
    print(f"New version ({new_version}): {new_results['pass_rate']:.2%}")
    print(f"Improvement: {improvement:+.2%}")
    
    # Fail if new version is worse
    if improvement < -0.05:  # 5% degradation
        print(f"ERROR: New prompt is worse than old (>{abs(improvement):.2%} degradation)")
        sys.exit(1)
    
    print("Prompt change validated")
    return improvement > 0

if __name__ == "__main__":
    test_prompt_change("v1", "v2")
```

Version model configurations and track performance.

### Model Configuration Versioning

```python
# models/model_config.py
from dataclasses import dataclass
from typing import Dict, Any
from datetime import datetime

@dataclass
class ModelConfig:
    """Versioned model configuration."""
    version: str
    embedding_model: str
    llm_model: str
    chunk_size: int
    chunk_overlap: int
    temperature: float
    max_tokens: int
    created_at: str
    description: str
    performance_metrics: Dict[str, Any] = None

class ModelConfigRegistry:
    """Registry for model configurations."""
    
    def __init__(self):
        self.configs: Dict[str, Dict[str, ModelConfig]] = {}
    
    def register(self, system_name: str, config: ModelConfig):
        """Register a model configuration."""
        if system_name not in self.configs:
            self.configs[system_name] = {}
        
        self.configs[system_name][config.version] = config
    
    def get(self, system_name: str, version: str = "latest") -> ModelConfig:
        """Get model configuration."""
        if system_name not in self.configs:
            raise ValueError(f"System '{system_name}' not found")
        
        if version == "latest":
            versions = sorted(self.configs[system_name].keys(), reverse=True)
            version = versions[0] if versions else None
        
        if version not in self.configs[system_name]:
            raise ValueError(f"Version '{version}' not found for '{system_name}'")
        
        return self.configs[system_name][version]

# Usage
registry = ModelConfigRegistry()

registry.register("rag_system", ModelConfig(
    version="v1",
    embedding_model="text-embedding-ada-002",
    llm_model="gpt-3.5-turbo",
    chunk_size=1000,
    chunk_overlap=200,
    temperature=0.7,
    max_tokens=1000,
    created_at=datetime.now().isoformat(),
    description="Initial RAG configuration"
))

registry.register("rag_system", ModelConfig(
    version="v2",
    embedding_model="text-embedding-3-small",
    llm_model="gpt-4o",
    chunk_size=800,
    chunk_overlap=150,
    temperature=0.7,
    max_tokens=1500,
    created_at=datetime.now().isoformat(),
    description="Upgraded to GPT-4o and new embeddings"
))
```

```python
# scripts/smoke_tests.py
import argparse
import requests
import sys
import time

def smoke_test_health(environment: str):
    """Test health endpoint."""
    url = f"https://api-{environment}.example.com/health"
    response = requests.get(url, timeout=5)
    
    if response.status_code != 200:
        print(f"ERROR: Health check failed with status {response.status_code}")
        return False
    
    data = response.json()
    if data.get("status") != "healthy":
        print(f"ERROR: Health check returned unhealthy status")
        return False
    
    print("✓ Health check passed")
    return True

def smoke_test_basic_query(environment: str):
    """Test basic query endpoint."""
    url = f"https://api-{environment}.example.com/query"
    response = requests.post(
        url,
        json={"query": "test query"},
        timeout=30
    )
    
    if response.status_code != 200:
        print(f"ERROR: Query failed with status {response.status_code}")
        return False
    
    data = response.json()
    if "answer" not in data:
        print("ERROR: Response missing 'answer' field")
        return False
    
    if len(data["answer"]) == 0:
        print("ERROR: Answer is empty")
        return False
    
    print("✓ Basic query test passed")
    return True

def smoke_test_latency(environment: str):
    """Test that latency is acceptable."""
    url = f"https://api-{environment}.example.com/query"
    
    start_time = time.time()
    response = requests.post(
        url,
        json={"query": "test"},
        timeout=30
    )
    latency = time.time() - start_time
    
    if response.status_code != 200:
        print(f"ERROR: Query failed")
        return False
    
    max_latency = 10.0  # 10 seconds
    if latency > max_latency:
        print(f"ERROR: Latency {latency:.2f}s exceeds maximum {max_latency}s")
        return False
    
    print(f"✓ Latency test passed ({latency:.2f}s)")
    return True

def main():
    parser = argparse.ArgumentParser(description="Run smoke tests")
    parser.add_argument("--environment", required=True, choices=["staging", "production"])
    args = parser.parse_args()
    
    print(f"Running smoke tests on {args.environment}...")
    
    tests = [
        smoke_test_health,
        smoke_test_basic_query,
        smoke_test_latency
    ]
    
    passed = 0
    failed = 0
    
    for test in tests:
        try:
            if test(args.environment):
                passed += 1
            else:
                failed += 1
        except Exception as e:
            print(f"ERROR: {test.__name__} failed with exception: {e}")
            failed += 1
    
    print(f"\nSmoke tests: {passed} passed, {failed} failed")
    
    if failed > 0:
        print("Smoke tests failed!")
        sys.exit(1)
    
    print("All smoke tests passed!")
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

## Rollback Strategies

Plan for rollback when deployments fail.

### Automatic Rollback

```python
# scripts/deploy_with_rollback.py
import subprocess
import sys
import time

def deploy_with_rollback(version: str):
    """Deploy with automatic rollback on failure."""
    print(f"Deploying version {version}...")
    
    # Deploy
    try:
        subprocess.run(
            ["kubectl", "set", "image", "deployment/rag-service", f"rag-service={version}"],
            check=True
        )
        subprocess.run(
            ["kubectl", "rollout", "status", "deployment/rag-service", "--timeout=5m"],
            check=True
        )
    except subprocess.CalledProcessError as e:
        print(f"Deployment failed: {e}")
        rollback()
        sys.exit(1)
    
    # Wait for deployment to stabilize
    time.sleep(30)
    
    # Run smoke tests
    try:
        subprocess.run(["python", "scripts/smoke_tests.py", "--environment", "production"], check=True)
    except subprocess.CalledProcessError:
        print("Smoke tests failed, rolling back...")
        rollback()
        sys.exit(1)
    
    print("Deployment successful!")

def rollback():
    """Rollback to previous version."""
    print("Rolling back deployment...")
    subprocess.run(["kubectl", "rollout", "undo", "deployment/rag-service"], check=True)
    subprocess.run(["kubectl", "rollout", "status", "deployment/rag-service"], check=True)
    print("Rollback complete")

if __name__ == "__main__":
    deploy_with_rollback(sys.argv[1])
```

## Common Mistakes

### 1. No CI/CD at all

Manual deployments are error-prone and slow.

**Problems:**
- Human error in deployment
- Inconsistent deployments
- Slow deployment process
- No automated testing
- Difficult to rollback

**Solutions:**
- Set up CI/CD pipeline
- Automate testing
- Automate deployments
- Use infrastructure as code
- Version control everything

CI/CD is essential - don't deploy manually.

### 2. Exact match tests for AI outputs

Using exact match tests that fail on non-deterministic outputs.

**Problems:**
- Tests fail randomly
- False negatives
- Can't catch real regressions
- Wastes time

**Solutions:**
- Use evaluation frameworks
- Set confidence thresholds
- Test score distributions
- Use semantic similarity

Never use exact match for AI outputs - use evaluations.

### 3. No prompt versioning

Not versioning prompts makes changes untrackable.

**Problems:**
- Can't track prompt changes
- Can't rollback prompt changes
- Can't test prompt impact
- No history

**Solutions:**
- Version prompts explicitly
- Track prompt changes
- Test prompt versions
- Store prompt history

Version prompts like code - they affect behavior.

### 4. No evaluation in CI

Deploying without evaluation testing.

**Problems:**
- Deploy broken systems
- Catch regressions late
- Poor quality deployments
- User impact

**Solutions:**
- Run evaluations in CI
- Set pass thresholds
- Fail on regressions
- Test before deployment

Evaluations are your quality gate - use them.

### 5. No rollback strategy

Can't recover from bad deployments.

**Problems:**
- Stuck with broken deployment
- Extended downtime
- Manual recovery needed
- User impact

**Solutions:**
- Plan rollback procedures
- Test rollback process
- Automate rollback
- Have rollback triggers

Always have a rollback plan - you'll need it.

### 6. Testing too slowly

CI pipeline takes too long, slowing development.

**Problems:**
- Slow feedback
- Developers wait
- Reduced productivity
- Less frequent deployments

**Solutions:**
- Use fast tests in CI
- Run comprehensive tests separately
- Parallelize tests
- Cache dependencies
- Optimize test execution

Fast CI keeps development velocity high.

### 7. No smoke tests

Deploying without post-deployment verification.

**Problems:**
- Deploy broken systems
- Catch issues late
- User impact
- No quick verification

**Solutions:**
- Run smoke tests after deployment
- Test critical paths
- Verify basic functionality
- Automate smoke tests

Smoke tests catch deployment failures quickly.

### 8. Ignoring evaluation costs

Running expensive evaluations too frequently.

**Problems:**
- High CI/CD costs
- Slow pipelines
- Budget overruns
- Wasted resources

**Solutions:**
- Use fast evaluations for CI
- Run comprehensive evaluations separately
- Cache evaluation results
- Optimize evaluation frequency

Balance thoroughness with cost and speed.

### 9. No model versioning

Not tracking model configurations and versions.

**Problems:**
- Can't track model changes
- Can't reproduce issues
- No model rollback
- Unclear what's deployed

**Solutions:**
- Version model configurations
- Track model performance
- Support model rollback
- Document model changes

Model configuration is code - version it.

### 10. Deployment without staging

Deploying directly to production.

**Problems:**
- Production failures
- User impact
- Difficult recovery
- High risk

**Solutions:**
- Deploy to staging first
- Test in staging
- Deploy to production after validation
- Use canary deployments

Always test in staging before production.
